# Список теорем и пояснения

Проверка гипотезы: оператор в узле Z восстанавливает сообщение по обрывкам из сети
быстрее, чем к нему напрямую придёт точное сообщение из A.

## Состав

- `Sarafan.lean` — формальная модель и теоремы (Lean 4 + Mathlib).
- `SarafanMosaic.lean` — асимметричная информация: мозаичный эффект, разделение секрета, рычаги, утечки.
- `SarafanCheapTalk.lean` — модель Кроуфорда–Собела: конфликт интересов ограничивает передачу информации.
- `SarafanExact.lean` — уточнения: точная теорема через число покрытия, цена незнания, обратная задача, утечки кругами.
- `SarafanDisclosure.lean` — постепенное раскрытие авторитетным источником: порядок раскрытия, молчание как сигнал.
- `SarafanActions.lean` — следствие: преждевременные действия на слухах и как раскрытие их сокращает.
- `simulation/simulate.py` — Монте-Карло на той же модели со случайными задержками, потерями и искажениями.
- `simulation/figures/` — результаты симуляции.

## Сборка Lean

```bash
# если Lean ещё нет:
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh

lake exe cache get     # скачать собранный Mathlib (несколько минут)
lake build             # проверить все доказательства
```

Если `lake build` прошёл без ошибок и предупреждений `sorry`, все теоремы доказаны.

**Статус проверки:** проект собран на Lean 4.35.0 с Mathlib v4.35.0 —
`Build completed successfully`, 32 + 12 + 11 + 15 + 12 + 9 = 91 теорема, `sorry` нет. Ключевые теоремы используют
только стандартные аксиомы Lean (`propext`, `Classical.choice`, `Quot.sound`);
проверить можно командой `#print axioms <имя теоремы>`.

Файл импортирует не весь Mathlib, а только нужные модули (~1850 файлов),
поэтому без `cache get` его можно собрать из исходников примерно за час.

| `SideInfo.goodColoring_zero_iff` | При нулевой ошибке это правильная раскраска графа путаницы (Witsenhausen, 1976) |

## Общая теорема

Обозначения: `M` — сообщения, возможные с точки зрения Z (априорное знание сужает `M`);
`r` — допустимая ошибка; `V(r)` — сколько сообщений попадает в шар ошибки радиуса `r`;
`d` — длина кратчайшего пути A→Z; `C` — пропускная способность минимального разреза
между A и Z; `tDirect` — момент прямой доставки.

**Необходимое условие (доказано в Lean):**

    log₂|M| − log₂V(r)  ≤  C · (tDirect − 1 − d)

Слева — сколько информации Z действительно нужно, справа — сколько сеть успевает доставить.

**Достаточное условие (теорема Шеннона о кодировании с потерями, в Lean не формализовано):**
при оптимальном кодировании и длинных сообщениях выполнения этого неравенства
с небольшим запасом достаточно для выигрыша.

## Точная теорема (постановка Wyner–Ziv, однократная передача)

A и сеть не знают, что известно Z. Знания Z — состояние `y`; `compat x y` означает,
что сообщение `x` не противоречит знаниям `y`. Кодер видит только `x`, Z — полученные биты и `y`.

Z восстанавливает сообщение с ошибкой ≤ r раньше прямой доставки **тогда и только тогда**, когда
сообщения можно раскрасить в 2^(C·(T − 1 − d)) цветов так, чтобы внутри каждого цвета
все сообщения, совместимые с одним и тем же состоянием знаний Z, укладывались в одну
допустимую ошибку. Доказано в Lean полностью, в обе стороны (при условии, что сеть
доставляет C бит за единицу времени после задержки d).

## Асимметричная информация (`SarafanMosaic.lean`)

| Теорема | Смысл |
|---|---|
| `context_decides` | Одна и та же подсказка не даёт постороннему ничего, а тому, у кого есть ключевое знание, — всё сообщение |
| `additive_private`, `additive_reveal` | Секрет — сумма долей: без любой одной доли остальные совместимы с каждым секретом ровно одним способом; все вместе раскрывают секрет |
| `shamir_reconstruct` | Схема Шамира: любые k долей однозначно восстанавливают секрет |
| `shamir_private` | Любые k − 1 долей не дают о секрете ничего: каждый секрет согласуется с ними ровно одним способом |
| `SideInfo.levers` | Больше знаний у Z, больше допустимая ошибка, шире сеть, меньше задержка, позже объявление ⇒ слухам не труднее |
| `SideInfo.announce_first` | Если объявить раньше, чем до Z могут дойти первые обрывки, слухи не выигрывают |
| `noLeak_anti_insiders`, `noLeak_anti_days` | Вероятность отсутствия утечки (1 − q)^(kT) падает с ростом числа посвящённых и срока |
| `leak_le`, `safe_window` | Риск утечки ≤ k·T·q; если k·T·q ≤ α, риск ≤ α |
| `noLeak_mul_le` | Риск утечки ≥ k·T·q / (1 + k·T·q): оценка сверху почти точна, риск растёт пропорционально k·T·q |

Пример правила безопасного окна (q = 1% в день на человека, допустимый риск 50%):
5 посвящённых — 10 дней, 50 посвящённых — 1 день. При 50 посвящённых за 10 дней
утечка происходит с вероятностью не меньше 5/6 (доказано; точное значение ≈ 99%).

## Конфликт интересов (`SarafanCheapTalk.lean`)

Отправитель знает θ ∈ [0, 1], получатель выбирает действие. Получатель хочет попасть в θ,
отправитель — в θ + b (b — конфликт интересов). Слова ничего не стоят и не проверяются.

| Теорема | Смысл |
|---|---|
| `IsEquilibrium.indiff` | На границе двух интервалов отправителю безразлично, какой назвать |
| `IsEquilibrium.gap_step` | Каждый следующий интервал длиннее предыдущего на 4b |
| **`crawford_sobel`** | В любом равновесии с N интервалами 2·N·(N − 1)·b < 1 |
| `fewer_intervals` | Если 2·n·(n − 1)·b ≥ 1, интервалов меньше n |
| `no_info` | При b ≥ 1/4 интервал один: слова не передают ничего |
| `exists_equilibrium` | Если 2·N·(N − 1)·b < 1, равновесие с N интервалами существует |
| **`equilibrium_exists_iff`** | Точный критерий: равновесие с N интервалами ⇔ 2·N·(N − 1)·b < 1 |

Следствие: за один разговор честно передаётся не больше log₂N(b) бит.
При b = 1% — 7 интервалов (≈ 2,8 бита), 8 уже невозможно; при b = 1/4 — 0 бит.
Предположение модели: получатель выбирает середину интервала (его оптимум при
квадратичных потерях и равномерном θ) — это свойство в Lean не выводится, а задано.

## Симуляция

```bash
cd simulation && python3 simulate.py
```

Вариант «настоящего сарафана» (повторение вместо кода, подтверждение от двух источников,
общий источник искажений): `python3 simulate.py gossip`.
Три политики официального раскрытия: `python3 simulate.py disclosure`.
Преждевременные действия 200 сотрудников при четырёх политиках: `python3 simulate.py actions`.

Параметры — в сигнатуре `simulate()`: длина сообщения, число фрагментов, длина маршрутов,
скорости каналов, доли потерь и искажений, доля сообщения, которую Z угадывает по контексту.
